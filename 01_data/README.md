## Project Overview

This project builds a complete end-to-end data pipeline for a fictional payment processing company, covering raw transaction ingestion, data cleaning and standardization, currency conversion, merchant enrichment, SQL analysis, ledger-to-gateway reconciliation, API response normalization, and dashboard data preparation.

The pipeline processes three source files — `transactions_raw.csv`, `merchant_master.csv`, and `exchange_rates.csv` — and produces 12 clean output files across four project parts. All monetary values are converted to USD. All scripts are written in Python using pandas and the standard library.

## Source Datasets

### transactions_raw.csv
30 raw payment transactions with intentional data quality issues: mixed merchant name casing and spacing (`"ALPHA MART"`, `"Alpha  Mart"`, `" alpha mart "`), status strings with embedded error codes (`"failed E05 timeout"`), risk scores in multiple formats (`"score:62"`, `"risk-83"`, `"75 "`), inconsistent gateway region casing, and amounts in INR/EUR/USD requiring currency conversion.

### merchant_master.csv
Reference table for 5 merchants: Alpha Mart (Grocery, APAC), Beta Stores (Electronics, APAC), City Pharma (Healthcare, EU), Delta Travels (Travel, US), Eco Home (Home, EU). Used for merchant name normalization and enrichment (merchant_id, category, region, account manager).

### exchange_rates.csv
Daily USD exchange rates for INR, EUR, and USD across 2026-03-01 to 2026-03-06. Joined to transactions on `(transaction_date, currency)` to produce `amount_usd`.

### ledger.csv / gateway.csv
Internal ledger (10 rows) and payment gateway log (9 rows) for reconciliation. Contains deliberate mismatches: 2 transactions missing from gateway, 1 missing from ledger, 2 amount discrepancies, and 1 status discrepancy.

### api_response_sample.json
Nested JSON from the QuickPay Settlement API. Two batches → six settlements across Alpha Mart (APAC) and Delta Travels (US). Three levels of nesting: `batches → merchant → settlements → bank`.

## How to Run

### Prerequisites

```bash
pip install pandas
```

Python 3.8+ and the standard library (`json`, `os`, `re`, `sqlite3`) are required. No other dependencies.

### Part 1 — Transaction Cleaning and Enrichment

```bash
python scripts/process_transactions.py
```

Reads `transactions_raw.csv`, `merchant_master.csv`, and `exchange_rates.csv` from the uploads directory. Performs all 10 cleaning and enrichment steps. Saves `cleaned_transactions.csv` and `merchant_risk_summary.csv` to `data/processed/`.

### Part 2 — SQL Analysis

Open `sql/analysis_queries.sql` in any SQLite-compatible tool (DB Browser for SQLite, DBeaver, or the built-in Python `sqlite3` module). Load `cleaned_transactions.csv` as the `transactions` table and run Q1–Q8 in sequence.

To run via Python directly:

```bash
python - << 'EOF'
import pandas as pd, sqlite3
df = pd.read_csv("data/processed/cleaned_transactions.csv")
con = sqlite3.connect(":memory:")
df.to_sql("transactions", con, index=False)
# paste any query here
EOF
```

### Part 3 — Ledger–Gateway Reconciliation

```bash
python scripts/reconciliation.py
```

Reads `ledger.csv` and `gateway.csv`. Identifies missing records in each direction, amount mismatches, and status mismatches. Saves five output files to `data/processed/` and `summary_metrics.json` to `04_python/`.

### Parts 3–4 — API Normalization and Dashboard Prep

```bash
python scripts/full_pipeline.py
```

Flattens `api_response_sample.json` into a tabular format and saves `api_normalized.csv`. Then reads `cleaned_transactions.csv` to produce four dashboard-ready aggregation CSVs: `daily_summary.csv`, `payment_method_breakdown.csv`, `region_breakdown.csv`, and `merchant_performance_summary.csv`.

## Key Findings

**Cleaning:** 12 raw merchant name variants collapsed to 5 canonical names. 7 distinct raw status strings reduced to 3 valid values. Risk scores extracted from 3 different formats (`"score:XX"`, `"risk-XX"`, plain integers with whitespace). 1 row (T011) had a null risk score — retained as null. Gateway region had 9 nulls — merchant master `default_region` used for flag calculations instead.

**Transaction flags:** 7 of 30 transactions were flagged `high_value_flag = 1` (all APAC, amount_usd > $5,000). 9 of 30 were flagged `high_risk_flag = 1` (risk_score ≥ 70 or status = chargeback). User U008 triggered 4 failed/chargeback transactions in a single day (2026-03-05) across two merchants — the strongest fraud signal in the dataset.

**GMV:** Total captured GMV of $82,355.50 across 19 captured transactions. Beta Stores ($33,431) and Alpha Mart ($29,985) together represent 77% of captured revenue. Eco Home had zero captured GMV — its only transaction was a chargeback of $6,649.

**Reconciliation:** 6 of 11 unique transaction IDs had at least one issue. Amount at risk: $15,090. The largest single concern is R005 ($7,200) — marked `success` in the ledger but `failed` in the gateway.

**SQL analysis:** APAC is the only region meeting both conditions of Q6 (avg risk > 50 AND > 20 transactions), with an average risk score of 65.48 across 21 transactions. All 4 merchants exceeded the 1% chargeback threshold (Q5), with Eco Home at 50% and Delta Travels at 25% — inflated by small transaction counts.

## Notes

All scripts use absolute paths that resolve to the local environment they were written in. To run on a different machine, update the `UPLOADS` and output directory path variables at the top of each script.

The `processed_at` column in `api_normalized.csv` is stored as a timezone-aware datetime (`datetime64[ns, UTC]`). If loading into a tool that does not support timezone-aware datetimes, convert with `.dt.tz_localize(None)` before export.

Exchange rates in this project are illustrative and do not reflect real market rates.
